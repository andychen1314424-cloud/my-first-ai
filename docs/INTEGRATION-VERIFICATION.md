## 本轮真实 API

| 方法 | 路径 | 结果 |
| --- | --- | --- |
| GET | `/api/finance/snapshot` | 账户、分类、负债、全部流水和指定月份预算 |
| POST | `/api/finance/transactions` | 新建，必须携带 `Idempotency-Key` |
| PUT | `/api/finance/transactions/:id` | 修改，服务端重新验证和回算 |
| DELETE | `/api/finance/transactions/:id` | 删除，204，服务端回算 |
| POST | `/api/finance/accounts` | 新建账户与初始余额 |
| PUT | `/api/finance/budget/:month` | 总预算及分类预算 |
| POST | `/api/finance/liabilities/:id/repayments` | 还款，204，必须携带 `Idempotency-Key` |

所有金额为安全整数分。SQLite 外键、严格表、事务、迁移校验、审计及持久化幂等凭证已实现。余额从初始余额和完整流水计算；转账不计收支，还款不计消费，退款冲减消费。修改/删除后同步回算。重复键同内容重放不重复入账，异内容返回 409。

还款在内部测试夹具中建立负债后验证；目前没有对用户开放新增负债的 HTTP API/界面，新空账本不能从界面直接录入负债。投资买卖、借出收回及借入尚未实现，后端明确拒绝，避免归为普通消费。快照暂返回全部历史，后续需要分页和服务端统计。

一致性备份和仅限空库的回滚已实现；自动备份计划、加密、恢复 UI 尚未实现。恢复步骤与审计边界见 [FINANCE-STORAGE.md](FINANCE-STORAGE.md)。

## 本机验证结果

环境：Windows、Node v24.22.1、npm 12.2.1、已安装 Chrome。`npm install` 完成，安装时审计为 0 个漏洞。使用本机 npm 工具目录提供命令，没有修改项目脚本来依赖该目录。

| 命令 / 验证 | 结果 |
| --- | --- |
| `npm install` | 依赖安装和 lockfile 更新成功 |
| `npm run typecheck` | 通过 |
| `npm run check` | TypeScript + Vite 构建成功，34/34 Node 测试通过 |
| `npm run test:e2e` | 7/7 通过，使用已有 Chrome，不下载浏览器 |
| 1440px 桌面、390px 手机视口 | 11 个路由无横向溢出；记账和项目实验台交互通过 |
| 浅色 / 深色视觉检查 | 工作台、Finance、实验台布局可用，检查时应用控制台无错误 |
| 真实本地 Ollama | `qwen3:4b` 经原实验台适配器生成 4 个任务，结构校验通过，耗时约 46.25 秒 |
| SQLite online backup | 本机命令成功生成并校验备份；快照一致性另有自动化测试 |

34 项 Node 测试覆盖原项目领域与 HTTP 协议、真实整数分、编辑/删除回算、转账/退款/还款、超额还款回滚、幂等重放/冲突/重启保留、6 个并发同键请求只入账一次、非法输入、Host/Origin、备份完整性、迁移版本/校验和、空库回滚、安全整数边界和无支出时的资金可支撑时间。

7 项浏览器测试覆盖：规则提案使用真实 ID 且必须确认；账户与三步记账；关闭页面后重新打开仍存在；修改/删除二次确认；手机全流程；原实验台任务/复盘/导出/删除/模型不可用状态；切换外壳保留未保存复盘；在 Shadow DOM 输入 N 不误触记账。

浏览器自动化中的模型服务为明确命名的协议 fixture，用于稳定验证流程；它不计为真实 AI 回复。上表的本机 Ollama 结果是另行实测，验证的是原实验台任务生成，未验证新助手聊天。全部自动化财务记录使用独立临时 SQLite，与用户账本隔离。

## 仍待完成与安全限制

- 新 AI 助手：真实聊天、流式输出、服务端会话历史、统一 Provider、`deepseek-r1:8b`，以及模型记账提案/确认接口。

- 新增负债、投资持仓/损益、借贷、账单导入、分类管理、服务端报告和备份恢复界面。
- 账号认证、权限控制、限流与 HTTPS 部署。原 `AGENTS.md` 未修改，继续仅监听 `127.0.0.1`，保留 Host/Origin 和本地模型白名单。手机不能直接访问电脑的回环地址。
- 无云端 Provider、无云端或付费回退；没有产生付费 API 调用。云模型预留与本地白名单扩展需下一轮按用户确认的范围实施。
- PWA 仍仅有 manifest/SVG 图标，没有 Service Worker。尚未做真实 iPhone Safari / Android 验证、无障碍全面审计、多用户和外网安全验收。

本轮可用于单人在本机录入经确认的账务。不得据本轮测试结果认定当前已支持公网访问、完整投资会计或真实 AI 财务助手。
